# 绮梦庄园：产品规格草案

> 工作名称，尚未确定正式名称。本文依据已确认需求制定，不代表已实现的功能。原来的合成收藏馆棋盘不属于当前主玩法。

## 1. 产品目标

微信小游戏：玩家创造喜欢的 3D 形象，经营从普通田园逐步成长为幻想家园的农场与牧场，以自己的角色拜访好友、分享外观和庄园。

核心循环：种植／饲养 → 成熟收获 → 出售与获得经营经验 → 解锁品种和土地 → 建设更漂亮的庄园。外观与收藏提供长期目标；不以战力为主要驱动。早期提出的女性玩家比例是定位假设，不是已验证指标；角色与服装支持不同玩家表达。

## 2. 第一轮可运行样板

目标是验证角色、经营场景、操作及风格能否共同成立，而不是声称完成商业上线。

- 人物：一套基础角色、预设选择和可见的面部参数调整；服装切换。
- 外观方案：保存、导入、导出，包含数据版本；错误方案不覆盖现有外观。
- 农场：种子选择、等级限制、播种、成熟、收获、出售。
- 牧场：购买已解锁动物、生产幼崽、收获及出售。
- 好友玩法演示：访问示例庄园，验证成熟批次偷取上限。模拟好友不得冒充真实微信关系。
- 展示：经营视角、角色近景；移动端布局与本地恢复。
- 资源：普通与幻想品种并列展示；未完成的专业模型必须标注为占位资产。

暂不进入本轮：照片 AI 捏脸、真实微信好友关系、线上账号及权威服务器、支付、广告、活动运营、海量服装、完整繁殖遗传系统。

## 3. 捏脸与换装

### 3.1 交互

每个部位先选预设，再调整参数。基础模式提供常用参数，专业模式逐步扩展；参数数量以有效控制与变形质量决定，不以滑杆数量验收。

重点部位：脸长脸宽、下颌与下巴、眉骨、眉毛位置及弯曲、眼距、眼宽、开合、内外眼角、眼睑弧度、鼻根鼻梁鼻尖鼻翼、嘴宽与上下唇。头型须受头发与服装适配边界约束。

眉形、睫毛、眼线、唇妆为独立资源层，不假设所有效果都能靠头模变形得到。默认左右联动；细分不对称在模型验证后开放。

支持数值显示与输入、局部重置、撤销／重做、前后对比、正侧面切换。编辑退出提示保留或放弃未保存修改。

### 3.2 外观分享数据

建议数据组成：`schemaVersion`、`baseModelId`、`modelVersion`、部位预设 ID、归一化参数、资源 ID、颜色、可选穿搭。必须限制长度、验证数值类型与范围、处理未知资源及不兼容版本。

早期可使用包含数据的编码文本；短码需要服务端存储与查询，不能在离线原型中假装存在。分享方案不自动授予未拥有服饰。模型升级必须提供迁移或保留旧版解释能力。

### 3.3 AI 后续接口

将来图片只用于生成已有参数体系内的起始方案，允许继续编辑。真人和动漫图需要分别评估；不承诺单张图精确复刻、不推断模型未支持的畸形头部。原图处理、删除期限、授权及训练使用规则需在接入前明确。当前不上传、不存储面部照片。

## 4. 农牧场与经济

等级解锁表为数据配置。5 级玉米、8 级西瓜、30 级仙草、50–60 级天马或麒麟只是用户示例，正式数值需通过产出与升级时长测算。

品种配置至少包括：ID、解锁等级、购买成本、生长／生产时长、成熟产量、售价、经验、模型与阶段资源。普通品种在高等级保留用途，避免低级土地与资源完全作废。

牧场把持续生产的成年种畜与本批产出的幼崽分开。好友不能偷成年种畜。偷来的幼崽只能出售，不可饲养、繁殖或转换成种畜，不绕过等级解锁。

初期只使用金币与经营经验，避免原型出现多种无法解释的代币。售卖、种子购买、动物购买的账目需明确；保持可重新开工的基础途径，防止买衣服后永久断产。

## 5. 偷取规则：已确认

针对每块田／生产单位的每批成熟产出，固定记下实际原始产量 `Q`。

```text
本批总可偷额度 = floor(Q / 2)
主人最低保留量 = ceil(Q / 2)
剩余可偷额度 = floor(Q / 2) - 本批已被偷数量
本次成功数量 = min(配置单次数量, 剩余可偷额度)
```

- 只有成熟且未被主人收获的批次可偷；不设额外等待主人时段。
- 所有好友共用同一个额度，不是每人可偷一半。
- 同一好友对同一批次最多成功偷一次；失败请求不消耗资格。
- 剩余额度为零提示“这批已经不能再摘取啦”；禁止发放零数量奖励。
- 主人可随时收走剩余产出，关闭批次。新批次使用新 ID 和新记录。
- 原始产量为 40 时，最多累计偷 20；41 时最多 20；1 时不可偷。稀有幼崽若希望可偷，需要产出数量设计配合，不能突破保底。
- 主人端提供来访和数量记录；不通过羞辱性文案刺激玩家关系。

线上必须由服务器验证成熟时间、身份、一次资格、余额和库存。扣减与奖励以事务或等价原子操作执行；请求携带幂等键，重试不重复发放；主人收获和好友偷取并发时由同一批次状态裁决。本地演示无法提供上述安全性，不能用于正式经济。

## 6. 微信适配

以分享邀请和游戏内关系为可规划入口；不假设能读取完整微信通讯录或自动识别所有好友。正式接入须以当时平台能力、权限与真机测试为准。

前后台切换保存进度、停止无意义渲染和音频；禁止依赖页面倒计时作为线上成熟依据。资源按场景和品类分包或按需加载；商业上线前验证加载、内存、发热、耗电与低端设备表现。

## 7. 验收与后续里程碑

1. 原型：操作链完整，错误输入不破坏存档，偷取案例及边界测试通过。
2. 美术样板：真实模型、两套衣服、一小块田地及动物在目标设备运行；近景与经营镜头都可读。
3. 联网切片：微信身份、好友邀请、云存档、权威经济与并发校验。
4. 内容扩展：等级经济表、成套服装、更多作物动物、教程和运营配置。

所有阶段分别标注已实现、模拟、占位和待接入。上线指标、帧率和包体预算以选定设备与平台限制实测制定，不用未经核实的同类产品数据作为保证。
