# 技术实施与交付边界

## 当前交付

依赖为零的浏览器交互原型、原创经营领域函数、规则单元测试、产品/美术制作规格和概念图。
浏览器原型不是微信小游戏构建，也不是生产后端。SVG 角色只验证预设、参数变化、服装选择和分享交互，不验证真实 3D 捏脸效果。

## 分层目标

1. 客户端表现：角色、动画、相机、场景、输入和 UI；界面不直接拥有生产奖励的权威。
2. 游戏规则：等级开放表、种子/种畜、成熟批次、产物、背包、订单及服装配方；使用明确配置，避免写死在按钮事件中。
3. 服务器权威：登录身份、成熟时间、余额、库存、访问资格、偷取额度与已访问记录；客户端只能提出操作请求。
4. 内容资源：头模、变形目标、服装、动物、植物、音频；必须带稳定 ID 与版本。

## 引擎选型

最终候选先以 Cocos Creator 3.x 为主，当前没有把版本或现有技能当成性能验证。必须使用真实头模和一块庄园完成微信真机样板后再锁定版本、渲染管线和预算。当前 Node/Web 原型可以直接评审交互，但不能直接当成引擎项目发布。

## 捏脸数据

外观保存需包含 schemaVersion、headModelVersion、presetIds、参数字典、眉毛/睫毛/妆容/发型资源 ID、颜色和服装选择。每个参数定义最小值、最大值、默认值与安全组合范围。导入先验证长度、版本、类型、有限数值、合法资源，禁止将分享码当作脚本执行。

本地分享码不是加密身份，不包含人脸照片或账号。生产短码需要后端保存快照、访问限制、资源版本迁移和失效提示。导入服装外观不意味着获得未拥有的服装；需显示缺失资源并使用回退。

AI 图片辅助暂缓。后续输出同一套参数结构，真人和动漫采用不同特征适配，不恢复奇异头部结构。先证明手工调整有效，再做自动拟合。

## 偷取服务端事务

每一成熟批次固定 initialYield 和 maturity 时间；可偷上限 floor(initialYield / 2)，主人保底 ceil(initialYield / 2)。每个访客每批成功一次。必须在同一事务内检查批次版本、所有权、成熟和额度，更新扣量及访客记录，同时发放库存。重试要有操作幂等键。原型 revision 字段仅辅助实现，不等于已经完成并发控制。

主人收获与访客偷取竞争同一批次状态，按服务器提交顺序决定；清空批次后禁止再次收获或偷取。养殖种畜不属于可偷产物。偷来的幼崽带不可繁殖、仅出售标记，不授予等级解锁。

## 微信社交

通过受平台支持的登录、邀请和游戏内好友关系实现访问。当前没有实现微信登录、支付、好友图谱读取、广告或云存储。真实接口接入前核对平台当前能力，不能默认能读取全部微信好友。

## 下一阶段放行条件

- 真实 3D 头模能完成至少五种明显不同的造型，正侧面与表情均通过检查。
- 两套服装在行走、采摘与主要捏脸组合下无明显穿模。
- 目标中低档手机上评估加载、内存、帧率、发热与后台恢复；目前无真机测试结果。
- 服务端并发、幂等、断线重试与存档迁移通过测试。
- 在完整循环可玩后再制作更多服装、等级和幻想品种。
