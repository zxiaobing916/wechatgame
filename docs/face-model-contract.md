# 角色捏脸：真实 3D 资产合同草案

当前网页中的二维参数示意只验证交互。本文件用于下一阶段头模、发型和五官资源制作，不代表这些资产已交付。

## 必须先统一的基准

基础头模使用中性表情和固定单位、朝向、骨架、顶点拓扑、UV 及版本。表情变形与捏脸变形区分命名。所有预设通过参数或经过验证的形态组合表示，不允许切眼型后破坏头模拓扑。

眼型预设可以一次设置多个相关参数；选预设后仍允许微调。更换眼型默认只影响眼部，不应悄悄重置嘴、鼻、服装。眉毛、睫毛、眼线等资源有独立 ID，并跟随相关变形。

## 第一批必须验证的控制

| 区域 | 参数 | 需要观察的副作用 |
| --- | --- | --- |
| 脸型 | 脸宽、脸长、颧骨宽、面颊饱满 | 太阳穴、发际线、脖颈接缝 |
| 下颌 | 下颌宽、下颌角、下巴长度、下巴前突 | 侧脸与张嘴表情 |
| 眼部 | 眼距、眼高、眼长、开合、内外眼角高度、眼窝深度 | 眼球暴露、闭眼穿插、睫毛位置 |
| 眉部 | 眉高、眉距、眉峰、眉尾高度、眉骨前突 | 眉形纹理变形与皮肤贴合 |
| 鼻部 | 鼻根高、鼻梁高、鼻梁宽、鼻尖突出、鼻翼宽 | 正面阴影与侧面轮廓 |
| 唇部 | 嘴宽、嘴高、上下唇厚、唇峰、嘴角高低 | 牙齿暴露、闭嘴密合、唇妆 |

数值范围先归一化表示，不把滑杆单位直接假设成厘米。每个参数的安全极值由绑定与变形测试决定。界面展示值、存档值和模型权重必须有唯一映射。

## 组合与预设验收

1. 准备圆润短脸、细长眼修长脸、宽下颌脸、柔和饱满脸、动漫大眼脸五组原创目标。
2. 每组检查正面、侧面、四分之三，固定灯光并保存截图。
3. 对每组执行眨眼、微笑、张嘴；检查眼睑、牙齿与唇部。
4. 对相互影响的参数组合验证极值，必要时加入修正形态，不以单滑杆正常代替组合通过。
5. 切换至少两种发型、头饰与耳饰；检查最大头宽、额头高和耳位。
6. 确认保存、导出、重新加载后外观一致；模型改版时验证旧码迁移。

## 微信性能验证

交互调参时允许重新计算变形，离开编辑器后可采用缓存或烘焙形态；是否可用需结合选定引擎验证。不要默认每帧让全部捏脸通道参与计算。分别测量一位主角与多位来访角色的内存、加载和帧时；分享方案数据与大体积资源分离。

## AI 后置接口

图片辅助最终只输出本合同支持的合法参数和资源选择。照片里不可观察的侧脸深度使用默认或低置信度结果，不声称准确恢复。动漫参考只转译五官比例，不自动生成畸形头部或未制作的发型。生成结果先预览，用户确认后保存；不影响手动捏脸路线。
