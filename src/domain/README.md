# 收获与偷取领域原型

`harvest.mjs` 为原创、零依赖 ES 模块，可用于浏览器演示及后续服务端实现。运行 `node --test tests/harvest.test.mjs` 验证规则。

## 固定规则

- 批次成熟产量 `initialYield` 在创建时确定；可偷总量为 `floor(initialYield / 2)`，不随剩余量重新计算。
- 每位访客每批次只能成功偷取一次；最后一次只发放剩余可偷数量。主人不能偷自己。
- 主人可以收获所有尚未被偷的产出；收获后批次关闭。未成熟不能偷、不能收。
- 单只幼崽批次不可偷，奇数批次为主人保留较多的一半。
- 偷来的幼崽仅可出售，不能成为种畜或用于繁殖。
- 当前原型将所有收获物作为可出售产物，种畜获取与繁殖资格另行实现；这不是已确认的主人幼崽养成规则。

## 接口

```js
const batch = createBatch({
  batchId: 'field-1:harvest-1', ownerId: 'player-1', productId: 'watermelon',
  kind: 'crop', initialYield: 40, maturesAt: 1760000000000,
});
const { batch: nextBatch, reward } = stealHarvest(batch, {
  visitorId: 'player-2', requestedAmount: 3, now: Date.now(),
});
```

`kind` 为 `crop` 或 `offspring`。时间统一采用非负整数毫秒。所有返回状态冻结，调用不会修改输入。业务拒绝抛出带 `code` 的 `HarvestError`。

## 线上服务必须补齐的事务边界

这些纯函数本身**不提供数据库事务、身份认证或并发安全**。两个请求读取同一个旧状态，各自计算结果，仍会发生超发；不能直接把客户端计算结果当作可信数据。

服务端必须在一个数据库事务中：验证登录身份和好友访问资格 → 读取当前批次 → 使用服务端时间和配表中的单次偷取数量执行转换 → 检查并更新 `revision` → 发放库存 → 写入日志 → 提交事务。版本冲突应重新读取当前状态再计算，禁止重复发放奖励。

主人收获也必须经过同样的事务边界。`ownerId`、访客身份、时间、产量、单次偷取数量及物品权限都不能信任客户端提交值。库存消费与繁殖服务必须再次验证来源和 `sellOnly` 权限。

好友关系、经验、金币出售价格、种植与繁殖计时、网络重试幂等键以及数据库持久化尚未实现。
